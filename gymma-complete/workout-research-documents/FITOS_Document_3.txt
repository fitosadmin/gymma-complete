================================================================================
                    FITOS — DOCUMENT 3
    MATHEMATICAL MAPPING & RECOMMENDATION ENGINE SPECIFICATION
                  Scoring Formulas, Workout Generation & Periodization
================================================================================

DOCUMENT PURPOSE
----------------
This document defines the complete mathematical model that transforms the
User Fitness Profile Vector (Document 1) and Exercise Profile Vectors
(Document 2) into a personalized workout plan. It is the algorithmic core
of FITOS.

Every formula, weight, threshold, and edge case is specified here so that
the engine produces deterministic, explainable, and auditable recommendations.

================================================================================

1. THE INPUT VECTORS
--------------------

1.1 USER FITNESS PROFILE VECTOR (From Document 1)
--------------------------------------------------
After the user completes the assessment, the engine computes an 8-dimensional
vector U = [u1, u2, u3, u4, u5, u6, u7, u8] where each dimension is normalized
to [0, 100].

| Dimension | Symbol | Source Field(s) | Calculation Logic |
|-----------|--------|-----------------|-------------------|
| Goal Alignment | G | S4_PRIMARY, S4_SECONDARY | See Section 2.1 |
| Recovery Capacity | R | S2_SLEEP, S2_STRESS, S2_NUTRITION, S2_OCCUPATION | See Section 2.2 |
| Mobility Score | M | S7_* (if shown) or default 50 | See Section 2.3 |
| Strength Level | S | S3_1RM ratios or bodyweight benchmarks | See Section 2.4 |
| Experience Score | E | S3_DURATION, S3_COMPOUNDS, S3_PROGRAM, S3_FREQUENCY | See Section 2.5 |
| Availability Score | A | S5_DAYS, S5_TIME, S5_GYM_TYPE | See Section 2.6 |
| Injury Risk | I | S0_*, S6_* | See Section 2.7 |
| Preference Alignment | P | S8_STYLE, S8_SPLIT, S8_CARDIO, S8_DISLIKES | See Section 2.8 |

1.2 EXERCISE PROFILE VECTOR (From Document 2)
---------------------------------------------
Every exercise e in the Gym Exercise Database has a vector
Ve = [ve1, ve2, ..., veN] defined in Document 2. For the matching engine,
we extract the following scalar fields:

| Symbol | Field | Meaning | Range |
|--------|-------|---------|-------|
| De | difficulty_score | Overall difficulty | [0, 100] |
| Ge | goal_compatibility[G_user] | Compatibility with user's primary goal | [0, 100] |
| Me | mobility_required | Minimum mobility score needed | [0, 100] |
| Ee | experience_minimum | Minimum experience to attempt | [0, 100] |
| Re | injury_risk_factor | Inherent injury risk of the exercise | [0, 100] |
| Pe | equipment_match | Does gym have equipment? | {0, 100} |
| Be | blacklist_flag | Is exercise in user's dislike list? | {0, 100} |
| Ce | contraindication_match | Does user have a contraindicated injury? | {0, 100} |

================================================================================

2. VECTOR COMPUTATION FORMULAS
------------------------------

2.1 GOAL ALIGNMENT (G)
----------------------
The user selects a primary goal G_p and optional secondary goal G_s from:
{Strength, Hypertrophy, Endurance, Power, General_Health, Recomposition}

G = 100 if primary goal is clear and unambiguous.
If secondary goal conflicts with primary (e.g., Primary=Endurance,
Secondary=Strength), apply a conflict penalty:

G = 100 - (Conflict_Penalty[G_p, G_s] * 15)

CONFLICT PENALTY MATRIX:

                | Strength | Hypertrophy | Endurance | Power | General | Recomp |
|----------------|----------|-------------|-----------|-------|---------|--------|
| Strength       | 0        | 0.3         | 0.8       | 0.1   | 0.2     | 0.3    |
| Hypertrophy    | 0.3      | 0           | 0.6       | 0.4   | 0.2     | 0.1    |
| Endurance      | 0.8      | 0.6         | 0         | 0.7   | 0.3     | 0.5    |
| Power          | 0.1      | 0.4         | 0.7       | 0     | 0.3     | 0.4    |
| General_Health | 0.2      | 0.2         | 0.3       | 0.3   | 0       | 0.1    |
| Recomposition  | 0.3      | 0.1         | 0.5       | 0.4   | 0.1     | 0      |

Example: Primary=Hypertrophy, Secondary=Endurance
G = 100 - (0.6 * 15) = 100 - 9 = 91

2.2 RECOVERY CAPACITY (R)
-------------------------
Inputs: S2_SLEEP (hours), S2_SLEEP_QUALITY (1-5), S2_STRESS (Low=1, Med=2, High=3),
S2_OCCUPATION (Sedentary=1, Light=2, Active=3, Very_Active=4),
S2_NUTRITION (Poor=1, Inconsistent=2, Consistent=3, Strict=4),
S2_ALCOHOL (drinks/week)

R_raw = (
  (S2_SLEEP * S2_SLEEP_QUALITY * 4) +           // Max = 12*5*4 = 240
  (S2_OCCUPATION * 15) +                        // Max = 4*15 = 60
  ((4 - S2_STRESS) * 20) +                      // Max = 3*20 = 60
  (S2_NUTRITION * 25) +                         // Max = 4*25 = 100
  (max(0, 21 - S2_ALCOHOL) * 1.5)               // Max = 21*1.5 = 31.5
)

R_max = 240 + 60 + 60 + 100 + 31.5 = 491.5
R = (R_raw / R_max) * 100  -> clamped to [0, 100]

Recovery Modifiers on Training Variables:
- R < 30: Reduce weekly volume by 30%, reduce intensity by 10%, max frequency = 3
- R 30-50: Reduce weekly volume by 15%, max frequency = 4
- R 50-70: Standard prescription
- R 70-85: Standard prescription, can tolerate higher volume
- R > 85: Can tolerate advanced periodization (high volume + high intensity blocks)

2.3 MOBILITY SCORE (M)
-----------------------
If Experience Score E < 20, M defaults to 50 (beginners are assumed to have
average mobility; they are not screened to avoid false negatives).

If E >= 20, M is computed from S7 responses:

M = (
  (S7_SQUAT_DEPTH_score * 25) +
  (S7_OVERHEAD_score * 25) +
  (S7_HINGE_score * 20) +
  (S7_LUNGE_score * 20) +
  (S7_ROTARY_score * 10)
)

Where each S7 response maps to a score:
  Yes = 25/25/20/20/10 (full points)
  Partial/Almost/Unstable = 60% of full points
  No = 20% of full points (minimum mobility, not zero to avoid total lockout)

2.4 STRENGTH LEVEL (S)
----------------------
If user provided 1RMs (S3_1RM_AWARE = true):
  Calculate relative strength ratios:
    Squat_Ratio = S3_SQUAT_1RM / S1_WEIGHT
    Deadlift_Ratio = S3_DEADLIFT_1RM / S1_WEIGHT
    Bench_Ratio = S3_BENCH_1RM / S1_WEIGHT

  Compare against sex-specific strength standards (Novice/Intermediate/Advanced):
    S = average_percentile_across_lifts * 100

If no 1RMs provided (E < 20 or S3_1RM_AWARE = false):
  S = E * 0.8  (Strength is estimated from experience proxy)

STRENGTH STANDARDS (Male, bodyweight multiplier):
  Lift        | Novice | Intermediate | Advanced | Elite
  ------------|--------|--------------|----------|-------
  Squat       | 1.0x   | 1.5x         | 2.0x     | 2.5x
  Deadlift    | 1.2x   | 1.8x         | 2.5x     | 3.0x
  Bench Press | 0.75x  | 1.25x        | 1.75x    | 2.25x

(Female standards are approximately 65-70% of male standards for lower body,
 55-60% for upper body, due to differences in fat-free mass distribution.)

2.5 EXPERIENCE SCORE (E)
------------------------
Inputs: S3_DURATION, S3_COMPOUNDS, S3_PROGRAM, S3_FREQUENCY

Duration_Points:
  Never = 0, <6mo = 15, 6-12mo = 35, 1-2yr = 55, 2-5yr = 80, 5+yr = 100

Compound_Points: Each of 5 lifts checked = +10 points (max 50)
Program_Points: S3_PROGRAM = true ? 15 : 0
Frequency_Points: 
  0 days/week = 0, 1-2 = 5, 3-4 = 10, 5-6 = 15, 7+ = 20

E = (
  Duration_Points * 0.50 +
  Compound_Points * 0.30 +
  Program_Points * 0.15 +
  Frequency_Points * 0.05
) -> clamped to [0, 100]

2.6 AVAILABILITY SCORE (A)
---------------------------
Inputs: S5_DAYS (1-7), S5_TIME (15-120 min), S5_GYM_TYPE

Gym_Type_Factor:
  Home = 8 (limited equipment), Commercial = 10, Outdoor = 7

A_raw = (S5_DAYS * 12) + (S5_TIME * 0.5) + Gym_Type_Factor
A_max = (7 * 12) + (120 * 0.5) + 10 = 84 + 60 + 10 = 154
A = (A_raw / A_max) * 100 -> clamped to [0, 100]

Availability determines:
  - Weekly training frequency (days/week)
  - Session duration (minutes)
  - Sets per session (volume budget)
  - Split type eligibility

2.7 INJURY RISK (I)
--------------------
I is a RISK INDEX, not a capacity score. Higher I means MORE restrictions.

Base_I = 0
If S0_Q2 or S0_Q3 (cardiovascular risk) = true: Base_I += 30
If S0_Q4 (musculoskeletal risk) = true: Base_I += 20
If S0_Q5 (medication) = true: Base_I += 10
If S6_CURRENT_INJURY = true: Base_I += S6_PAIN_SCALE * 5
If S6_PAST_SURGERY = true: Base_I += 15
If S6_PHYSIO = true: Base_I += 10 (but also triggers conservative programming)

I = min(Base_I, 100)

I modifies:
  - MAX_INTENSITY = 100 - (I * 0.4)  [If I=50, max intensity = 80%]
  - VOLUME_MODIFIER = 1 - (I * 0.003)  [If I=50, volume = 85% of standard]
  - EXERCISE_BLACKLIST: Any exercise with contraindication matching S6_INJURY_LIST

2.8 PREFERENCE ALIGNMENT (P)
----------------------------
P is computed AFTER exercise matching, not before. It is a post-hoc score
that measures how well the generated plan aligns with user preferences.

For the matching engine, preferences act as FILTERS and WEIGHTS:
  - S8_STYLE filters equipment type (free weights vs machines vs calisthenics)
  - S8_SPLIT filters split type options
  - S8_DISLIKES populates EXERCISE_BLACKLIST
  - S8_CARDIO determines conditioning volume allocation

P is not used to select exercises; it is used to RANK competing exercises
that have already passed hard filters.

================================================================================

3. THE EXERCISE MATCHING ALGORITHM
-----------------------------------

3.1 HARD FILTERING (PASS/FAIL)
------------------------------
For each exercise e in Gym_Exercise_Database:

FILTER 1: Experience Gate
  if Ee > E: REJECT (exercise too advanced)
  Rationale: Beginners should not attempt Olympic lifts or complex barbell work.

FILTER 2: Equipment Gate
  if Pe == 0: REJECT (gym does not have required equipment)
  Rationale: A home gym without a barbell cannot program barbell squats.

FILTER 3: Blacklist Gate
  if Be == 0: REJECT (user explicitly dislikes this exercise)
  Rationale: Adherence is higher when hated exercises are avoided.

FILTER 4: Contraindication Gate
  if Ce == 0: REJECT (user has injury that contraindicates this exercise)
  Rationale: Safety first. No exceptions.

FILTER 5: Mobility Gate
  if Me > M: REJECT (user lacks required mobility)
  Rationale: Loading a movement pattern with insufficient mobility causes
  compensation and injury. If Me > M, the engine selects the REGRESSION
  (from exercise_progressions table) and re-evaluates.

After hard filtering, we have a CANDIDATE SET C of exercises that are
SAFE and APPROPRIATE for the user.

3.2 SOFT SCORING (RANKING)
--------------------------
For each exercise e in Candidate Set C, compute MATCH_SCORE(e, U):

MATCH_SCORE(e, U) = (
  w1 * Ge +                    // Goal compatibility (30%)
  w2 * (100 - |De - E|) +      // Difficulty fit (25%)
  w3 * (100 - |Me - M|) +      // Mobility fit (10%)
  w4 * (100 - Re) +            // Safety margin (15%)
  w5 * Pe +                    // Equipment preference (10%)
  w6 * muscle_priority(e, U)   // Muscle targeting (10%)
)

Where:
  w1 = 0.30, w2 = 0.25, w3 = 0.10, w4 = 0.15, w5 = 0.10, w6 = 0.10

muscle_priority(e, U) calculation:
  For each muscle in user's S4_TARGET_AREAS:
    if muscle in e.primary_muscles: +30 points
    if muscle in e.secondary_muscles: +15 points
    if muscle in e.tertiary_muscles: +5 points
  Sum and normalize to [0, 100]. If no target areas specified, default = 50.

The engine sorts C by MATCH_SCORE descending and selects the top N exercises
needed to fill the workout plan.

================================================================================
3.3 DIFFICULTY FIT CURVE
--------------------------
The term (100 - |De - E|) is a simple linear fit, but we can improve it with
a bell curve to prefer exercises SLIGHTLY below the user's level (safer) rather
than exactly at their level.

DIFFICULTY_FIT(e, E) = 100 * exp( - ((De - (E - 10))^2) / (2 * sigma^2) )

Where:
  - The target difficulty is shifted 10 points below user experience (E - 10)
    to ensure exercises are challenging but not at the failure threshold.
  - sigma = 20 (standard deviation of the bell curve)

This means:
  - If De = E - 10: Perfect fit = 100 points
  - If De = E: 88 points (slightly too hard)
  - If De = E - 30: 61 points (too easy, but acceptable for warm-ups or deloads)
  - If De = E + 20: 61 points (too hard, risky)

3.4 GOAL COMPATIBILITY WEIGHTING
---------------------------------
The goal compatibility Ge is not a single scalar. It is a vector:
  Ge = [Ge_strength, Ge_hypertrophy, Ge_endurance, Ge_power, Ge_health]

The engine selects the component matching the user's PRIMARY goal:
  Ge = Ge[G_user_primary]

If the user has a SECONDARY goal, a bonus is added:
  Ge_bonus = 0.15 * Ge[G_user_secondary]
  Ge_total = Ge + Ge_bonus (capped at 100)

Example: User wants Hypertrophy (primary) + Strength (secondary).
  Exercise: Barbell Back Squat
  Ge_hypertrophy = 85, Ge_strength = 95
  Ge_total = 85 + (0.15 * 95) = 85 + 14.25 = 99.25 -> capped at 100

4. WORKOUT GENERATION RULES
---------------------------

4.1 VOLUME CALCULATION (SETS PER WEEK PER MUSCLE GROUP)
----------------------------------------------------------
Total weekly volume is determined by Experience (E) and Recovery (R).

BASE_VOLUME = 
  if E < 20:  10 sets/week per muscle group (MEV - Minimum Effective Volume)
  if E 20-40: 12 sets/week per muscle group
  if E 40-60: 15 sets/week per muscle group (MAV - Maximum Adaptive Volume)
  if E 60-80: 18 sets/week per muscle group
  if E > 80:  20 sets/week per muscle group (MRV - Maximum Recoverable Volume)

RECOVERY_MODIFIER = R / 100

ADJUSTED_VOLUME = BASE_VOLUME * RECOVERY_MODIFIER

Example: E = 55 (Intermediate), R = 70 (moderate recovery)
  BASE_VOLUME = 15
  ADJUSTED_VOLUME = 15 * 0.70 = 10.5 sets/week per muscle group

This is a CONSERVATIVE starting point. The engine can increase volume by 10%
per mesocycle if recovery metrics (subjective readiness, performance) are positive.

4.2 INTENSITY CALCULATION (%1RM or RPE)
----------------------------------------
Intensity is determined by Goal (G) and Experience (E).

GOAL-BASED INTENSITY RANGES:

| Goal         | Novice (E<20) | Intermediate (E 20-60) | Advanced (E>60) |
|--------------|---------------|------------------------|-----------------|
| Strength     | 70-80% 1RM    | 80-90% 1RM             | 85-95% 1RM      |
| Hypertrophy  | 65-75% 1RM    | 70-80% 1RM             | 75-85% 1RM      |
| Endurance    | 50-60% 1RM    | 55-65% 1RM             | 60-70% 1RM      |
| Power        | N/A           | 60-70% 1RM (speed)     | 75-85% 1RM      |
| General      | 60-70% 1RM    | 65-75% 1RM             | 70-80% 1RM      |
| Recomp       | 65-75% 1RM    | 70-80% 1RM             | 75-85% 1RM      |

RPE CONVERSION (if user prefers RPE, from S8_RPE):
  RPE 10 = 0% reps in reserve (true 1RM)
  RPE 9  = 1 rep in reserve (~95% 1RM for 1 rep, ~90% for 3 reps, ~85% for 5 reps)
  RPE 8  = 2 reps in reserve (~90% for 1 rep, ~85% for 3 reps, ~80% for 5 reps)
  RPE 7  = 3 reps in reserve (~85% for 1 rep, ~80% for 3 reps, ~75% for 5 reps)

The engine uses Mike Tuchscherer's RPE chart for conversion:
  %1RM = f(RPE, target_reps) from standard RPE tables.

4.3 FREQUENCY CALCULATION (DAYS PER WEEK)
------------------------------------------
Frequency is determined by Availability (A) and Recovery (R).

MAX_FREQUENCY = floor( (A * 7) / 100 )  // Max possible days from availability

RECOVERY_LIMIT =
  if R < 30: 2 days/week
  if R 30-50: 3 days/week
  if R 50-70: 4 days/week
  if R 70-85: 5 days/week
  if R > 85:  6 days/week

ACTUAL_FREQUENCY = min(MAX_FREQUENCY, RECOVERY_LIMIT, S5_DAYS)

Example: A = 70 (user says 4 days/week), R = 60, S5_DAYS = 4
  MAX_FREQUENCY = floor(4.9) = 4
  RECOVERY_LIMIT = 4
  ACTUAL_FREQUENCY = min(4, 4, 4) = 4 days/week

4.4 SPLIT TYPE SELECTION
-------------------------
Split type is determined by ACTUAL_FREQUENCY (F) and Experience (E).

| Frequency | Experience < 20 | Experience 20-40 | Experience 40-60 | Experience > 60 |
|-----------|----------------|------------------|------------------|-----------------|
| 1 day     | Full Body      | Full Body        | Full Body        | Full Body       |
| 2 days    | Full Body      | Full Body        | Full Body        | Upper/Lower     |
| 3 days    | Full Body      | Full Body        | Full Body        | Push/Pull/Legs  |
| 4 days    | Full Body      | Upper/Lower      | Upper/Lower      | Upper/Lower     |
| 5 days    | Full Body      | Upper/Lower      | Push/Pull/Legs   | Push/Pull/Legs  |
| 6 days    | Full Body      | Upper/Lower      | Push/Pull/Legs   | Bro Split / Custom |

If user has S8_SPLIT preference and it is COMPATIBLE with the frequency-experience
matrix, the engine uses the preference. If incompatible, the engine shows a
warning: "Your preferred split requires 5 days/week. You selected 3 days/week.
Defaulting to Full Body."

4.5 SESSION STRUCTURE (PER WORKOUT)
-------------------------------------
Each session follows a hierarchy:

1. WARM-UP (5-10 min)
   - Dynamic mobility for the movement patterns of the day
   - Activation sets for primary muscles (2 sets at 50% working weight)

2. PRIMARY COMPOUND (1-2 exercises)
   - Highest difficulty, highest load
   - 3-5 sets, goal-specific rep range
   - 3-5 min rest

3. SECONDARY COMPOUND / ACCESSORY (2-3 exercises)
   - Moderate difficulty, moderate load
   - 3-4 sets, moderate rep range
   - 2-3 min rest

4. ISOLATION / PREHAB (2-3 exercises)
   - Lowest difficulty, targeted muscle work
   - 3-4 sets, higher rep range
   - 1-2 min rest

5. CONDITIONING (optional, based on S8_CARDIO)
   - Low: 5 min light cardio
   - Moderate: 10 min intervals or steady-state
   - High: 15-20 min HIIT or steady-state

VOLUME PER SESSION = ADJUSTED_VOLUME / ACTUAL_FREQUENCY

Example: ADJUSTED_VOLUME = 10.5 sets/week for chest, F = 3 days/week
  Chest volume per session = 10.5 / 3 = 3.5 sets
  In a Push day (chest + shoulders + triceps), chest gets 3-4 sets,
  shoulders get 3-4 sets, triceps get 3-4 sets.

5. PROGRESSIVE OVERLOAD LOGIC
-----------------------------

5.1 DOUBLE PROGRESSION MODEL (Novice-Intermediate, E < 60)
-----------------------------------------------------------
For each exercise, the user has a TARGET REP RANGE (e.g., 8-12 reps).

Week 1: Select weight where user can perform 3 sets of 8 reps with 2 RIR.
Week 2: Attempt 3 sets of 9 reps at same weight.
Week 3: Attempt 3 sets of 10 reps at same weight.
...
Week N: When user hits 3 sets of 12 reps, increase weight by 2.5-5% and reset
to 3 sets of 8 reps at the new weight.

This is the simplest, most reliable model for beginners because it does not
require 1RM testing and provides clear progression landmarks.

5.2 LINEAR PERIODIZATION (Intermediate, E 40-70)
-------------------------------------------------
Mesocycle = 4 weeks

Week 1: Volume accumulation, moderate intensity (70-75% 1RM), high volume (15-18 sets)
Week 2: Volume accumulation, moderate intensity (72-77% 1RM), high volume (16-19 sets)
Week 3: Intensification, high intensity (80-85% 1RM), moderate volume (12-15 sets)
Week 4: Deload, low intensity (60-65% 1RM), low volume (8-10 sets)

Repeat with 2.5-5% load increase from Week 1 baseline.

5.3 DAILY UNDULATING PERIODIZATION (DUP) (Advanced, E > 60)
------------------------------------------------------------
Each training day has a different focus:

Day 1 (Strength): 3-5 reps, 85-90% 1RM, 4-6 sets per exercise
Day 2 (Hypertrophy): 8-12 reps, 70-80% 1RM, 3-4 sets per exercise
Day 3 (Power/Endurance): 3-5 reps speed work OR 15+ reps, 50-60% 1RM

This provides concurrent development of multiple qualities and manages fatigue
by varying the stimulus daily.

5.4 AUTO-REGULATION VIA RPE/RIR
-------------------------------
If user selects RPE preference (S8_RPE = "RPE"), the engine uses auto-regulation:

TARGET_RPE = 
  if Goal = Strength: 8-9 (1-2 reps in reserve)
  if Goal = Hypertrophy: 7-8 (2-3 reps in reserve)
  if Goal = Endurance: 6-7 (3-4 reps in reserve)

If user reports RPE > TARGET_RPE for 2 consecutive sessions on the same exercise,
the engine REDUCES load by 2.5% (fatigue accumulation).
If user reports RPE < TARGET_RPE - 1 for 2 consecutive sessions,
the engine INCREASES load by 2.5% (adaptation occurred).

6. EDGE CASES & EXCEPTION HANDLING
-----------------------------------

6.1 USER HAS NO AVAILABLE EXERCISES AFTER FILTERING
----------------------------------------------------
Cause: Gym equipment is too limited OR injury flags are too restrictive.

Resolution:
  1. Check if ANY movement pattern has >=1 exercise after filtering.
  2. If a pattern is completely empty (e.g., no SQUAT exercises due to knee injury
     AND no equipment), the engine selects the closest regression chain exercise
     that bypasses the injury (e.g., Glute Bridge instead of Squat).
  3. If still empty, the engine falls back to BODYWEIGHT exercises (BW equipment
     is always assumed available).
  4. If still empty, the engine generates a MOBILITY-ONLY plan with the message:
     "Your current constraints limit resistance training. This plan focuses on
     movement quality and pain-free range of motion. Please consult a medical
     professional before adding load."

6.2 USER SELECTS CONFLICTING GOALS AND AVAILABILITY
---------------------------------------------------
Example: Goal = Power, Availability = 1 day/week, 20 minutes/session.

Resolution:
  1. The engine computes a FEASIBILITY SCORE:
     FEASIBILITY = (A * 0.4) + (E * 0.3) + (R * 0.3)
     If FEASIBILITY < 40 for the selected goal, the engine flags a conflict.
  2. The engine presents a message: "Your goal (Power) typically requires 4-5 days/week
     and 60+ minutes/session for effective adaptation. With your current availability
     (1 day, 20 min), we recommend switching to General Health or adjusting your
     schedule. Would you like to:
     a) Adjust goal to General Health (recommended)
     b) Keep goal but accept minimal progress
     c) Update availability"
  3. If user keeps goal, the engine generates the best possible plan but marks it
     as "Suboptimal — progress will be slow."

6.3 USER HITS PLATEAU (PERFORMANCE STALL)
------------------------------------------
Detection: If user fails to increase reps or load for 3 consecutive weeks on
3+ exercises.

Resolution (based on E):
  - E < 40: Deload week (reduce volume by 40%, keep intensity), then resume.
  - E 40-70: Change exercise variation (e.g., Back Squat -> Front Squat),
    or implement a 2-week intensification block.
  - E > 70: Implement block periodization (accumulation -> transmutation -> realization).

6.4 USER HAS HIGH INJURY RISK (I > 60)
---------------------------------------
Resolution:
  - Cap all exercises at Difficulty <= 30 (Tier 1-2 only).
  - Replace all barbell work with dumbbell or machine equivalents.
  - Add 2 prehab/rehab exercises per session targeting the injured area.
  - Reduce volume by 30% and increase rest periods by 50%.
  - Flag for trainer review if available.

6.5 USER IS PREGNANT/POSTPARTUM (S0_Q6 = true)
----------------------------------------------
Resolution:
  - Blacklist all supine exercises after first trimester.
  - Blacklist all maximal effort (RPE > 8) exercises.
  - Blacklist Valsalva-inducing movements (heavy squats/deadlifts).
  - Cap intensity at 70% 1RM (or RPE 7).
  - Add pelvic floor and core stability work.
  - Recommend medical clearance every 4 weeks.

6.6 USER IS OVER 65 (S1_AGE > 65)
----------------------------------
Resolution:
  - Prioritize machine-based and bodyweight exercises (lower stability demand).
  - Increase volume, decrease intensity (higher rep ranges, 12-15 reps).
  - Add 2 balance/stability exercises per session (fall prevention).
  - Increase rest periods by 25%.
  - Prioritize power training (light loads, fast concentrics) for functional aging.

7. THE COMPLETE RECOMMENDATION PIPELINE
----------------------------------------

STEP 1: INGEST USER VECTOR U
  Compute G, R, M, S, E, A, I, P from assessment responses.

STEP 2: LOAD GYM EXERCISE DATABASE
  Filter global database by gym_id (gym owner pre-filter).

STEP 3: APPLY HARD FILTERS
  For each exercise e in Gym DB:
    if Ee > E: remove
    if Pe == 0: remove
    if Be == 0: remove
    if Ce == 0: remove
    if Me > M: remove (and queue regression for re-evaluation)
  Result: Candidate Set C

STEP 4: COMPUTE MATCH SCORES
  For each e in C:
    MATCH_SCORE(e, U) = weighted sum of goal fit, difficulty fit, mobility fit,
                          safety margin, equipment preference, muscle priority.
  Sort C by MATCH_SCORE descending.

STEP 5: DETERMINE PROGRAM PARAMETERS
  F = ACTUAL_FREQUENCY (from A, R, S5_DAYS)
  V = ADJUSTED_VOLUME (from E, R)
  Intensity_Range = GOAL_INTENSITY (from G, E)
  Split = SPLIT_TYPE (from F, E, S8_SPLIT)

STEP 6: ALLOCATE VOLUME TO MUSCLE GROUPS
  For each major muscle group:
    Sets_per_week = V_muscle (from base volume + recovery modifier)
    Sets_per_session = Sets_per_week / F

STEP 7: SELECT EXERCISES FOR EACH SESSION
  For each session in the split:
    1. Select PRIMARY compound: highest MATCH_SCORE, covers most target muscles.
    2. Select SECONDARY compound: next highest MATCH_SCORE, different pattern.
    3. Select ACCESSORY/ISOLATION: fill remaining volume for target muscles.
    4. Ensure no muscle group exceeds Sets_per_session cap.
    5. Ensure at least 1 exercise per major muscle group in the split.

STEP 8: ASSIGN SETS, REPS, REST, RPE
  Based on goal, experience, and periodization model.

STEP 9: OUTPUT WORKOUT PLAN
  JSON structure with:
    - metadata (user_id, plan_id, generated_at, version)
    - program_parameters (frequency, split, volume, intensity_model)
    - sessions[] (day_1, day_2, ...)
      - exercises[] (exercise_id, name, sets, reps, rest, rpe, notes)
    - progression_rules (how to advance next week)
    - safety_flags (injury warnings, contraindications)

STEP 10: STORE & TRACK
  Save plan to user_plans table.
  Initialize performance_log for tracking reps, load, RPE over time.
  Set review_trigger for plateau detection (3 weeks).
